强制击杀目标实体：对玩家和生物走正常死亡流程，对掉落物、经验球等非生物实体直接移除。该命令无法被装备或状态效果抵抗，也无法被不死图腾救回；基岩版中创造模式玩家不受影响。

### 原理

`/kill` 与普通攻击、坠落等伤害来源走的是两条完全不同的路径。普通伤害会先扣除目标的生命值，再经过护甲、保护附魔、抗性效果的层层减伤；而 `/kill` 会直接对目标施加一次「强制击杀」——它不结算生命值扣减，也不理会任何防御手段，直接把活体实体送入死亡状态。因此在基岩版中，无论目标剩余多少生命值、穿戴多好的装备，只要被 `/kill` 选中就会立即死亡，手持的不死图腾也不会触发。Java 版的历史实现很好地印证了这一点：早期 `/kill` 通过施加 3.4×10^38 点「虚空伤害」来确保必定致死，1.20 起改用专门的 generic_kill 伤害类型，目的始终是绕过一切防御结算。

`/kill` 对不同性质的实体处理方式不同。对玩家、怪物、动物这类「活体」实体，命令会触发完整的死亡流程：实体播放死亡动画、在聊天栏广播死亡信息、按正常规则掉落战利品，史莱姆和岩浆怪等会在死亡时分裂的生物也会正常分裂出更小的个体。对掉落物、经验球、弹射物这类没有死亡流程的「非生物」实体，`/kill` 会把它们直接从世界中移除，不产生任何掉落或动画。理解这条分界线很重要，因为它决定了你用它清理实体时是否会留下大量掉落物。

因为活体实体会经历真正的死亡事件，`/kill` 也能驱动依赖死亡的一套系统。被击杀的玩家会计入 `deathCount` 准则的计分板、进入重生流程，其掉落的物品也会留在原地；命令执行成功时会返回「被杀实体数量」作为成功计数，失败（例如目标解析不到任何实体）则返回失败信号。这个成败信号可以被 [`/execute`](../execute/) 的 `if` 条件或条件连锁命令方块读取，用来判断某个实体是否仍然存在。边界情况包括：基岩版中创造模式玩家会被命令跳过，当选择器选中的目标全部是创造模式玩家时命令判定失败；由命令方块这类非实体执行者执行且未指定目标时，命令同样会失败。

### 语法

`/kill [target: target]`

基岩版自 0.16.0 加入 `/kill` 以来，命令语法保持稳定，只有一个可选参数，没有出现过 Java 版那样多次改动的多版本语法。

### 参数

- `[target: target]` — 目标参数，类型为「玩家名或实体选择器」。指定要击杀的目标，可以是玩家名（如 `Steve`）或 `@p`、`@a`、`@e`、`@s` 等选择器。该参数可选：省略时默认以命令执行者自己为目标（等价于 `@s`）；如果执行者是命令方块这类非实体，又未指定目标，命令会失败。

### 示例

**击杀自己：**
<CmdChat>`/kill`

省略目标参数，默认击杀命令执行者自己。玩家会立即死亡、进入重生流程，聊天栏显示对应的死亡信息。

**击杀指定玩家：**
<CmdChat>`/kill Steve`

击杀名为 `Steve` 的在线玩家。若该玩家不在线或名字写错导致解析不到目标，命令会失败。

**清除所有掉落物：**
<CmdChat>`/kill @e[type=item]`

移除世界中所有掉落物实体，不产生任何掉落，常用于清理卡顿来源。它与 [`/clear`](../clear/) 作用对象不同：前者清理掉在地上的物品实体，后者清理玩家物品栏中的物品。

**清除所有僵尸：**
<CmdChat>`/kill @e[type=zombie]`

击杀世界中所有僵尸。它们会播放死亡动画并按正常规则掉落战利品，而不是像掉落物那样被直接移除。

**清除除玩家外的所有实体：**
<CmdChat>`/kill @e[type=!player]`

击杀所有非玩家实体，包括怪物、动物、掉落物、经验球、弹射物等。其中生物走死亡流程并掉落战利品，掉落物等非生物实体被直接移除，常用于地图或服务器的大扫除。

**清除带有特定标签的实体：**
<CmdChat>`/kill @e[tag=cleanup]`

击杀所有带有 `cleanup` 标签的实体。常与 [`/tag`](../tag/) 配合，先用 `/tag` 给临时实体打上标签，再用此命令做定向批量清理。

### 基岩版注意

- 需要 OP 等级 1，且世界必须开启「允许作弊」，否则命令无法使用。
- 基岩版中创造模式玩家无法被 `/kill` 击杀：当选择器选中的所有目标都是创造模式玩家时，命令判定失败。
- 与 Java 版的差异：Java 版需要权限等级 2，基岩版只需 OP 等级 1；Java 版的参数名为 `<targets>`，基岩版为 `target: target`；Java 版可接受玩家 UUID 作为目标，基岩版仅接受玩家名或选择器。
- 目标参数省略时默认指向命令执行者自己；若执行者是命令方块这类非实体，未指定目标会导致命令失败。
- `/kill` 会触发真实的死亡事件，因此会计入 `deathCount` 准则的计分板，也会让玩家进入重生流程。

### 常见问题

<details>
<summary>为什么 /kill 杀不死创造模式的玩家？</summary>

在基岩版中，创造模式玩家免疫 `/kill` 造成的死亡，这是游戏内置的保护机制，避免误操作直接击杀正在建造的玩家。需要先通过 [`/gamemode`](../gamemode/) 把目标切换到生存或冒险模式，再执行 `/kill`。

</details>

<details>
<summary>用 /kill 清理掉落物和 /clear 有什么区别？</summary>

两者作用对象不同。`/kill @e[type=item]` 移除的是已经掉在地上的掉落物实体，而 `/clear` 清除的是玩家物品栏中的物品，二者常配合使用以彻底清理物品。

</details>

<details>
<summary>为什么 /kill @e[type=!player] 之后地上还有掉落物？</summary>

被击杀的生物会正常掉落战利品，这些掉落物作为新的实体留在地面。如果希望连掉落物一起清理，可以在之后追加执行 `/kill @e[type=item]`。

</details>

### 相关命令

- [`/execute`](../execute/) — 改变执行者与条件，实现「当某实体存在时击杀」等组合逻辑。
- [`/tag`](../tag/) — 给实体打标签，配合 `/kill @e[tag=...]` 实现定向批量清理。
- [`/clear`](../clear/) — 清除玩家物品栏中的物品，与 `/kill @e[type=item]` 作用对象互补。
- [`/summon`](../summon/) — 生成实体，与 `/kill` 一增一删，常用于临时实体的生命周期管理。
