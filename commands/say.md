`/say` 是最短的广播命令：一句话，全服可见。它比看上去多两个特性——文本里可以嵌目标选择器，游戏会把 `@p` 这类写法替换成对应实体的名字；消息前面会自动加一个来源前缀，区分是玩家发的还是命令方块发的。

### 原理

`/say` 的参数类型是 `message`，官方定义是"可以包含空格和选择器的纯文本"。这句话里的"选择器"是关键：解析时游戏会把文本里的 `@p`、`@a`、`@s` 这类选择器求值，替换成匹配到的实体名字，而不是原样显示 `@p` 三个字符。

所以 `/say 欢迎 @p` 出来的不是"欢迎 @p"，而是"欢迎 Steve"。

消息发出时前面会带一个来源标记：

- 玩家在聊天栏执行，前缀是 `[玩家名]`。
- 命令方块执行，基岩版前缀是 `[!]`。

这个前缀由游戏自动添加，命令行里控制不了。想让消息不带前缀、完全自定义排版，就得换 `/tellraw`。

另外，官方把这条命令标成"不需要开启作弊"——单人世界关掉作弊选项后仍然可用，这是它和 `/tellraw`、`/titleraw` 的又一个区别。

### 语法

`/say <message>`

### 参数

- `<message>` — 要发送的文本。可以带空格，不需要加引号；可以嵌选择器；可以写 `§` 颜色码。

### 示例

**最简单的广播**：

<CmdChat>`/say 服务器将在 5 分钟后重启`

**嵌入玩家名**：

<CmdChat>`/say 欢迎 @p 进入服务器`

最近的那名玩家会被替换进去。

**用标签筛人再报名字**：

<CmdChain>`/say @a[tag=just_finished] 完成了挑战`

命令方块执行时，匹配到的玩家名会出现在 "完成了挑战" 前面。命令方块没有执行者，所以 `@s` 匹配不到任何目标，要用标签或 `@p` 这类不依赖执行者的选择器。

**带颜色**：

<CmdChat>`/say §e注意：§c今晚 22:00 维护`

**和 tellraw 对照**：同样一句话，`/say` 会自动加 `[!]` 前缀，`/tellraw` 不加。

<CmdChat>`/tellraw @a {"rawtext":[{"text":"§e注意：§c今晚 22:00 维护"}]}`

### 与 /tellraw 的分工

| | `/say` | `/tellraw` |
|---|---|---|
| 内容 | 纯文本 + 选择器 | rawtext，可插分数、玩家名、本地化词条 |
| 前缀 | 自动加 `[!]` 或 `[玩家名]` | 无，完全自定义 |
| 换行 | 不支持 | 支持 `\n` |
| 需要作弊 | 否 | 是 |
| 适合 | 快速喊话、调试、简单公告 | 正式公告、状态栏、带数据的消息 |

判断标准很简单：需要插分数或控制排版就 `/tellraw`，只是想说句话就 `/say`。

### 基岩版注意

- 命令方块执行 `/say` 时前缀是 `[!]`，Java 版是 `[@]`。这是版本差异，抄 Java 教程会对不上。
- `message` 是单行参数，**不能换行**。写 `\n` 会原样显示成字符，不会断行。
- 不能插分数。要显示计分板数值必须用 `/tellraw` 里的 `score` 组件。
- `§` 颜色码有效，但只影响本条消息，不影响后续。
- 官方标注不需要开作弊，但多人服务器里仍受操作员权限约束——非 OP 玩家不一定能用。
- 文本里如果确实要显示 `@p` 这三个字符，需要绕开选择器解析，否则会被替换。

### 常见问题

<details>
<summary>消息里 @p 没被替换成名字</summary>

两种情况：一是从命令方块执行且没有玩家在附近，选择器匹配不到目标；二是文本里的 `@` 后面跟的不是合法选择器写法，游戏当成普通文字处理了。

</details>

<details>
<summary>为什么前缀是 [!] 而不是我的名字</summary>

那是命令方块发的。`[!]` 是基岩版给命令方块消息打的标记，玩家在聊天栏执行才会显示 `[玩家名]`。

</details>

<details>
<summary>能不能只发给某个人</summary>

不能。`/say` 固定全服可见。要定向发送用 `/tellraw <玩家> <rawtext>`。

</details>
