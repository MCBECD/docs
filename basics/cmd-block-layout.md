讲一条链怎么摆，写字最费劲：「指令 1 在箭头起点，2 到 9 依次指向它，注意 25 是条件连锁」——读者得在脑子里把九个方块摆一遍，还容易摆错。截图能看懂，但改一个方块就得重新截。

这套写法换一种表达：**像在游戏里摆方块一样，一行一行写出来**。一个字符一个方块，写完直接渲染成立体图，改一个字就能重画。

### 一分钟上手

三个方块的链，重复方块起头，后面两个连锁：

```cmdblock
R>  C>  C>
```

`R` 是重复方块，`C` 是连锁方块，`>` 表示箭头朝东。图可以拖动转视角。

### 符号表

| 符号 | 方块 | 说明 |
|------|------|------|
| `I` | 脉冲方块 | 橙色，每次通电执行一次 |
| `C` | 连锁方块 | 青色，被前一个方块触发 |
| `R` | 重复方块 | 紫色，每游戏刻执行 |
| `i` `c` `r` | 同上，有条件 | 小写表示「有条件」：四个侧面的箭头纹理会断开一个缺口，正面的菱形框与色点不变 |
| `.` `_` | 空气 | 虚线格子，用来占位对齐 |

六种状态一起看：

```cmdblock
I  i  C  c  R  r
```

从左到右：脉冲、脉冲（有条件）、连锁、连锁（有条件）、重复、重复（有条件）。

### 朝向

方块符号后面紧跟一个方向符，就是箭头朝哪边。不写默认朝东。

| 符号 | 朝向 | 对应的 facing_direction |
|------|------|------------------------|
| `>` | 东 | 5 |
| `v` | 南 | 3 |
| `<` | 西 | 4 |
| `^` | 北 | 2 |

折线摆放时，方向得跟着拐：

```cmdblock
R>  C>  C>
.   .   Cv
.   .   C<
```

第二行那个 `Cv` 朝南，第三行的 `C<` 朝西。

### 排列规则

一行是一条 z 轴上的线：**第一行是 z=0，往下递增**；**第一列是 x=0，往右递增**。每个 token 之间必须有空格。

空出来的位置要用 `.` 占着，否则后面的方块会整体左移：

```cmdblock
I>  C>  C>
.   .   C>
.   .   Cv
```

### 一个真实的例子

雪球菜单第一组的九个方块，用这套写法就是一行：

```cmdblock
R>  C>  C>  C>  C>  C>  C>  C>  C>
```

指令 1 起头，2 到 9 依次接在后面。配合正文里标出每条指令干什么，读者照着摆就不会错位。

### 逐面微调

字符网格能表达"哪一格放什么、箭头朝哪"，表达不了"这个面的贴图再转 90°"。需要精调时，把 `cmdblock` 里的内容换成 JSON——同一个代码块，两种写法都认。

JSON 就是渲染器的输入格式，一个方块一项：

| 字段 | 含义 |
|---|---|
| `x` `y` `z` | 坐标，整数；`y` 省略按 0 |
| `kind` | `impulse` / `impulse-cond` / `chain` / `chain-cond` / `repeat` / `repeat-cond` / `air` |
| `facing` | `2` 北、`3` 南、`4` 西、`5` 东 |
| `faces` | 可选，六个面各自的旋转角 |

`faces` 的键是 `front` `back` `left` `right` `top` `bottom`，值是角度，取 0 / 90 / 180 / 270。没写的面用默认值：只有 `bottom` 默认 180°，其余 0°——顶底共用一张图，底面不转过来就是反的。

```cmdblock
{
 "v": 1,
 "blocks": [
  { "x": 0, "y": 0, "z": 0, "kind": "repeat", "facing": 5 },
  { "x": 1, "y": 0, "z": 0, "kind": "chain", "facing": 5 },
  { "x": 2, "y": 0, "z": 0, "kind": "chain-cond", "facing": 5, "faces": { "top": 180 } }
 ]
}
```

第三个方块的顶面转 180°，看上去箭头朝后。**这只改贴图朝向，不改 `facing`**：链的走向、红石行为、执行顺序全由 `facing` 决定，`faces` 纯粹是视觉微调，用来把图案摆到你想要的样子。

排布复杂时不必手写。站里的 `/editor` 是个独立工具页：网格上点格子摆方块，选中后在面板里逐面 ±90°，最后点「从当前生成」拿到这段 JSON，粘进代码块即可。

### 常见错误

- **连写没空格**：`R>C>` 会被当成一个 token，渲染时会显示红色报错；写成 `R>  C>`。
- **方向符写反**：`>` 是东、`<` 是西，和数学符号一致；`^` 是北、`v` 是南，和屏幕上下一致。
- **忘了占位**：第二行少写一个 `.`，后面的方块整体左移一格。

语法写错时，页面上不会出图，而是原地显示一条红色提示，写清是第几行第几个 token 出的问题。

### 目前的限制

- 只支持单层（y=0）。叠层的排布暂时画不出来。
- 没有箭头连线。链的方向靠方块自身的箭头纹理表达，长链看起来会有点密。
- 方块纹理取自 Mojang 官方资源包示例（`github.com/Mojang/bedrock-samples`）。每个文件是 16×64 的四帧 flipbook，四帧图案相同、亮度渐亮又渐暗，游戏里就是那种呼吸感；页面取第 2 帧（最亮帧）当静态图。
- 六个面只用四张图，分配照官方 `blocks.json`：正面 `front`、背面 `back`、东西两侧 `side`、顶面与底面 `conditional`。顶底共用一张，所以底面还要再转 180° 才是正的——同一张 PNG 用在两个方向，方向不对就会上下颠倒。
- 有条件时东西两侧也换成 `conditional`，正面与背面保持原图。这是官方模型的做法：条件标记在侧面与顶面的缺口上，箭头面本身不变。
