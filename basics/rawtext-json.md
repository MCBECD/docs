基岩版所有富文本——聊天消息、屏幕标题、告示牌、成书、NPC 名字——底层都是同一套格式：**原始 JSON 文本**（rawtext）。它由一组"内容组件"拼成，每个组件负责一段内容：一段死文字、一个本地化词条、一个计分板分数，或者一个实体的名字。

这套格式最容易被误用的一点，是把它当成模板去算字符串。它算不了：没有拼接、没有截断、没有条件判断。能动的只有它读到的数据。

### 结构

根节点只有两种形态：一个纯文本字符串，或者一个带 `rawtext` 属性的对象。

```json
{"rawtext":[{"text":"hello "},{"text":"world"}]}
```

`rawtext` 必须是数组，至少一个元素，空数组会出错。数组里的元素按顺序拼起来，最后显示成一句话。

### 四种内容组件

每个元素是一个内容组件，用哪个字段决定它显示什么：

| 类型 | 必要字段 | 显示内容 |
|---|---|---|
| 纯文本 | `text` | 字符串本身 |
| 翻译文本 | `translate` | 玩家语言对应的本地化词条 |
| 计分板分数 | `score` | 某个目标上某个持有者的分数 |
| 实体名称 | `selector` | 匹配到的实体名字，多个用逗号连接 |

**`text`** 是字符串，换行必须写 `\n`：

```json
{"rawtext":[{"text":"第一行\n第二行"}]}
```

**`score`** 要两个字段：

```json
{"score":{"name":"@s","objective":"金币"}}
```

`name` 可以是选择器、玩家名、实体的计分板 ID，写 `*` 表示**读这句话的人自己**。`objective` 是计分项名称，必须和创建时完全一致。

**`selector`** 直接给一个选择器：

```json
{"selector":"@a[tag=finished]"}
```

**`translate`** 给一个本地化键名，找不到对应语言就查 `en_us.lang`，再找不到就当普通格式化字符串处理：

```json
{"translate":"commands.op.success","with":["朋友"]}
```

`with` 是填占位符用的，可以写成字符串数组，也可以写成对象形式的文本组件（对象里用 `rawtext` 给出匹配项列表）。

### 一个组件只显示一种内容

同一个对象里写了多个必要字段时，按 **`translate` > `text` > `score` > `selector`** 的顺序只取优先级最高的那个，其余忽略。

```json
{"text":"这段不会显示","translate":"commands.op.success","score":{"name":"*","objective":"金币"}}
```

上面这个组件只显示翻译文本。

### 嵌套

每个内容组件还可以带自己的 `rawtext` 扩展列表，显示在基础内容之后。子级先被解析成文本，再回传给父级：

```json
{"rawtext":[{"text":"§e金币 ","rawtext":[{"score":{"name":"*","objective":"金币"}}]}]}
```

实际写的时候很少嵌套，平铺更清楚。

### 样式只有 § 码

基岩版 rawtext 不支持 Java 那样的 `"color"`、`"bold"` 字段，也不能用十六进制色值。颜色、加粗、斜体全部靠 `§` 加一个字符：

| 码 | 效果 | 码 | 效果 |
|---|---|---|---|
| `§0`–`§9` `§a`–`§f` | 颜色 | `§l` | 加粗 |
| `§r` | 复位 | `§o` | 斜体 |
| `§k` | 乱码 | `§n` | 下划线 |
| `§m` | 删除线 | `§b` `§e` | 常见高亮色 |

`§r` 一定要在换色后补上，否则后面所有文字会继承上一个颜色。

### 动态内容是怎么来的

JSON 本身不会动。屏幕上的数字会变，是因为它每次渲染时重新去读计分板：

<CmdRepeat>`/titleraw @a actionbar {"rawtext":[{"text":"§e金币 §f"},{"score":{"name":"*","objective":"金币"}}]}`

这条命令每刻跑一次，`金币` 涨了，屏幕上的数字跟着涨。所谓"用 JSON 做动画"，机制就是这个——**分数在动，JSON 只是每刻重新读一遍**。

同理，`selector` 匹配到的目标变了，显示的名字就变了；`translate` 的 `with` 参数变了，填进去的词就变了。

JSON 内部没有任何条件逻辑，所以"第 3 帧显示这个、第 5 帧显示那个"要靠外部命令按分数筛选：

<CmdChain>`/titleraw @a[scores={帧=3}] actionbar {"rawtext":[{"text":"加载中 ▮▮▮▯▯"}]}`

<CmdChain>`/titleraw @a[scores={帧=5}] actionbar {"rawtext":[{"text":"加载中 ▮▮▮▮▮"}]}`

帧号来自一个每刻自增的计分板分数，切换由选择器的 `scores` 完成，和 JSON 无关。

### 用在哪些地方

`tellraw` 的消息、`titleraw` 的标题与副标题、NPC 的名字、书与笔的内容、告示牌的文字，用的都是这套格式。

但有一条例外必须记住：**`score` 和 `selector` 只在"流动文本"里生效**，也就是聊天消息和屏幕标题。写进告示牌、成书、物品名里，这两类组件不会显示任何内容。

### 易错点

- 整条命令必须写在一行，JSON 里出现真实回车会直接解析失败。
- 字符串里的双引号要写成 `\"`，反斜杠写成 `\\`。
- `rawtext` 写成空数组 `[]` 会报错，至少要有一个元素。
- `objective` 拼错不会报错，只是那块内容静默消失。
- `score` 读不存在的计分项时不显示内容，`name` 写 `*` 是唯一例外。
- `selector` 匹配不到目标时同样不显示。做公告时如果玩家名那块空了，多半是选择器没匹配到人，不是 JSON 写错。
- `translate` 里的 `%` 要写成 `%%`，`%%` 最终输出成一个 `%`。
- 一个元素只显示一种内容，想同时显示文字和分数，就拆成两个元素。
