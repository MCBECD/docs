基岩版没有可点击的界面，菜单和交互只能靠别的输入。最省事的一种输入就是**视角**：抬头当确认、低头当取消、左右看当切换。代价是零——不需要物品、不需要实体、不需要额外方块。

前提是把角度对应关系记准，写反一个符号，命令就永远匹配不到。

### 原理

选择器的四个角度参数是一组区间，不是单个值：

| 参数 | 含义 |
|---|---|
| `rx` | 最大垂直旋转角（pitch 上限） |
| `rxm` | 最小垂直旋转角（pitch 下限） |
| `ry` | 最大水平旋转角（yaw 上限） |
| `rym` | 最小水平旋转角（yaw 下限） |

只写上限或只写下限时，另一侧没有限制。两边都写就夹成一段扇区。

**垂直方向（pitch）以水平为 0°**：抬头为负，正上方是 -90°；低头为正，正下方是 +90°。所以：

- `rx=-88` → pitch ≤ -88°，几乎仰面朝天
- `rxm=88` → pitch ≥ 88°，几乎垂直向下

**水平方向（yaw）**：0° 朝正南，90° 朝正西，-90° 朝正东，±180° 朝正北。`rym=-45,ry=45` 就是以正南为中心的 90° 扇区。

关键在于这套过滤是**瞬时求值**：每一刻按玩家当前朝向重新判断，玩家一转视角，匹配结果立刻变。所以视角当输入是实时的，不需要额外检测。

### 三种常用写法

下面的例子用 `scores={菜单=N}` 当开关。这是计分板的条件写法：先 `/scoreboard objectives add 菜单 dummy` 建一个目标，再用 `/scoreboard players set @s 菜单 1` 把某个玩家的状态写成 1，选择器里写 `scores={菜单=1}` 就只匹配状态为 1 的人。

**抬头确认**：条件写成 `rx=-88`，配合状态分数，避免菜单关着也被触发。

<CmdChain>`/tp @a[scores={菜单=1},rx=-88] 5000 70 5000`

**低头取消**：条件写成 `rxm=88`，把状态清回 0。

<CmdChain>`/scoreboard players set @a[scores={菜单=!0},rxm=88] 菜单 0`

**左右看切换**：两个扇区分别对应"上一项"和"下一项"。

<CmdChain>`/scoreboard players remove @a[scores={菜单=1..6},rym=-60,ry=-20] 菜单 1`

<CmdChain>`/scoreboard players add @a[scores={菜单=1..6},rym=20,ry=60] 菜单 1`

### 凝视：把"持续看"变成"看了多久"

单个瞬间的角度只能表示"正在看"，表示不了"看了多久"。要看够一段时间才触发，得配一个计数器：

<CmdChain>`/scoreboard players add @a[rx=-85] 凝视 1`

<CmdChain>`/scoreboard players set @a[rxm=-84] 凝视 0`

<CmdChain>`/execute as @a[scores={凝视=20..}] run tellraw @s {"rawtext":[{"text":"已进入菜单"}]}`

第一条给正在抬头的人加 1，第二条把视线一离开就清零，第三条在连续抬头满 20 刻（1 秒）时触发。整段挂在延迟 0 的重复方块上。

要看更久就改阈值，`20..` 是 1 秒，`60..` 是 3 秒。这种写法比"必须精确对准某个角度"宽容得多，玩家不用把视角摆得像在做校准。

### 示例

**丢雪球丢不出去时用视角兜底**：菜单打开状态下用视角确认，菜单关闭时视角不触发任何东西。

<CmdRepeat>`/execute as @a[scores={菜单=1..6}] at @s run titleraw @s actionbar {"rawtext":[{"text":"抬头确认 / 低头关闭"}]}`

<CmdChain>`/scoreboard players set @a[scores={菜单=1..6},rx=-88] 菜单 0`

第二条在确认后把分数清零，菜单关闭，视角随即失效——这就是"确认一次只执行一次"的自然实现，不需要额外的去重逻辑。

**按朝向分流的传送门**：站在同一个位置，朝东走和朝西走进不同的门。

<CmdChain>`/tp @a[x=100,y=64,z=100,r=2,rym=-135,ry=-45] 200 70 200`

<CmdChain>`/tp @a[x=100,y=64,z=100,r=2,rym=45,ry=135] -200 70 -200`

### 基岩版注意

- pitch 的范围是 -90 到 90，不是 0 到 180。写成 `rx=88` 会匹配到低头的人，和直觉相反。
- yaw 的 0° 在正南，不是正北。`rym=0,ry=90` 是从正南转到正西这四分之一圈。
- 角度区间是闭区间，两个参数的顺序必须"最小在前、最大在后"。写反了不会报错，只是永远匹配不到。
- 视角参数只能用于有朝向的实体，命令方块自身没有朝向意义上的 pitch/yaw，别在 `as @s` 后面指望它。
- 玩家在旁观模式下视角仍然有效，检测照样命中。需要排除时加 `m=!spectator`。
- 这套判断依赖客户端上报的朝向，网络延迟下会有 1 到 2 刻的滞后，做高精度判定时把阈值放宽一点。
