## 标签标准

MCBECD 文档系统通过 `tags` 字段为每篇文档附加检索标签。标签用于站点前端的分类筛选、搜索索引和内容推荐。本文档定义了标签的完整规范：分类体系、命名规则、每篇文档的必填标签、可选标签、以及站点如何消费标签数据。

### 为什么需要标签标准

在引入标签标准之前，MCBECD 的文档中标签使用极为混乱：有的文档没有 `tags` 字段，有的使用了无意义的占位符（如 `["标签1", "标签2"]`），有的标签名缺乏一致性。这导致站点无法进行有效的分类筛选，用户也无法通过标签快速定位所需内容。

标签标准的制定目标是：

- **可检索性**：每篇文档都能通过至少 2 个标签被精确定位
- **一致性**：所有贡献者使用相同的标签名，避免同义词分裂（如同时存在「玩家」和「player」）
- **完备性**：标签分类体系覆盖所有文档类型，不留空白
- **可扩展性**：新增标签时不破坏现有体系，通过层级关系自然融入

### 标签分类体系

MCBECD 的标签分为三大层级：**领域标签**（Domain Tags）、**场景标签**（Scenario Tags）、**属性标签**（Attribute Tags）。每篇文档至少需要一个领域标签和一个场景标签。

#### 领域标签

领域标签描述命令或文档所操作的核心对象。这是最粗粒度的分类，对应 Minecraft 游戏中的主要概念。

| 标签名 | 说明 | 典型文档 |
|--------|------|----------|
| `玩家` | 以玩家为直接操作目标的命令 | `/gamemode`、`/tp`、`/give`、`/kill`、`/effect`、`/xp`、`/enchant` |
| `实体` | 以非玩家实体为操作目标的命令 | `/summon`、`/kill`（实体部分）、`/execute as @e` |
| `方块` | 操作世界中方块的命令 | `/setblock`、`/fill`、`/clone` |
| `世界` | 操作世界层面属性的命令 | `/time`、`/weather`、`/difficulty`、`/gamerule` |
| `物品` | 操作物品栏中物品的命令 | `/give`、`/enchant`、`/clear`（待添加） |
| `粒子` | 操作粒子效果的命令 | `/particle` |
| `音效` | 操作声音播放的命令 | `/playsound`、`/title` |
| `计分板` | 操作计分板系统的命令 | `/scoreboard` |
| `标签` | 操作实体标签的命令 | `/tag` |
| `传送` | 涉及位置移动的命令 | `/tp`、`/execute`（位置子命令） |
| `执行` | 命令执行上下文控制 | `/execute` |
| `信息` | 显示信息给玩家的命令 | `/title`、`/tellraw`（待添加） |
| `状态` | 查询或修改游戏状态的命令 | `/gamerule`、`/difficulty` |

#### 场景标签

场景标签描述命令的典型使用环境。一个命令可以有多个场景标签。

| 标签名 | 说明 |
|--------|------|
| `命令方块` | 主要在命令方块中使用（循环/连锁/条件） |
| `聊天栏` | 可以在聊天栏中直接使用 |
| `地图制作` | 常用于地图制作场景 |
| `服务器` | 服务器管理常用 |
| `自动化` | 用于自动化的循环/连锁系统 |
| `生存` | 生存模式玩家也能用到 |
| `创造` | 创造模式调试常用 |
| `红石` | 与红石电路配合使用 |
| `数据追踪` | 使用计分板追踪数据 |
| `条件判断` | 涉及 `if/unless` 条件逻辑 |
| `多人` | 多人服务器场景常用 |
| `NPC` | 与 NPC 交互相关 |

#### 属性标签

属性标签提供额外的元信息，帮助用户快速判断命令的特性。

| 标签名 | 说明 |
|--------|------|
| `需要OP` | 需要操作员权限才能执行 |
| `OP1` | 需要 OP 等级 1 |
| `OP2` | 需要 OP 等级 2 |
| `危险` | 可能造成不可逆操作（如 `/kill`、`/fill`） |
| `可逆` | 操作可以轻松撤销 |
| `批量` | 支持批量操作多个目标 |
| `单目标` | 每次只能操作一个目标 |
| `多目标` | 可以同时操作多个目标 |
| `即时` | 效果立即生效 |
| `延迟` | 需要延迟才能看到效果 |
| `循环` | 通常配合循环命令方块使用 |
| `基岩独有` | 基岩版特有功能或语法 |
| `版本敏感` | 不同版本语法差异较大 |
| `网易差异` | 网易版与国际版存在差异 |

### 文档类型与必填标签

不同类型的文档有不同的标签要求。

#### 命令文档（commands/*.mdx）

命令文档的 `tags` 字段**必填**，且至少包含以下标签：

1. **1 个领域标签**：描述命令的核心操作对象
2. **1-2 个场景标签**：描述命令的主要使用场景
3. **属性标签**（可选但推荐）：标注命令的关键特性

示例：

```yaml
---
title: "/give  给予物品"
category: commands
tags: ["物品", "玩家", "聊天栏", "OP1"]
---
```

```yaml
---
title: "/execute  执行命令"
category: commands
tags: ["执行", "条件判断", "命令方块", "自动化", "OP2", "批量", "基岩独有"]
---
```

```yaml
---
title: "/scoreboard  计分板"
category: commands
tags: ["计分板", "数据追踪", "命令方块", "聊天栏", "OP1", "多人", "循环"]
---
```

#### 社区文档（数字编号.mdx）

社区文档的 `tags` 字段**必填**，用于标识内容类型和技术栈。

社区文档必须包含以下标签：

1. **1 个内容类型标签**：描述文档的内容形式
2. **1 个技术栈标签**：描述文档使用的技术手段

内容类型标签：

| 标签名 | 说明 |
|--------|------|
| `教程` | 手把手教学类文档 |
| `工具` | 实用工具/系统类文档 |
| `玩法` | 游戏玩法创意类文档 |
| `技巧` | 技巧/窍门类文档 |
| `红石电路` | 红石电路设计类文档 |

技术栈标签：

| 标签名 | 说明 |
|--------|------|
| `计分板` | 使用计分板技术 |
| `命令方块` | 使用命令方块 |
| `标签系统` | 使用 `/tag` 命令 |
| `execute` | 使用 `/execute` 的复杂链 |
| `原版` | 仅使用原版命令，无需附加包 |

示例：

```yaml
---
title: "雪球菜单"
category: community
tags: ["工具", "命令方块", "计分板", "execute", "原版"]
---
```

```yaml
---
title: "在线时间"
category: community
tags: ["工具", "计分板", "命令方块", "循环", "原版"]
---
```

#### 基础文档（basics/*.mdx）

基础文档的 `tags` 字段**可选**。如果添加，建议使用 `标准` 标签表示这是一篇规范文档。

### 标签书写规则

1. **中文名称**：所有标签使用简体中文，不使用英文标签名（如用 `玩家` 而非 `player`）
2. **无空格**：标签名不包含空格。如果需要两个词，直接拼接（如 `数据追踪`）
3. **用方括号**：在 frontmatter 中，标签写在方括号内，用双引号包裹，逗号分隔
4. **顺序**：先写领域标签，再写场景标签，最后写属性标签
5. **数量**：每篇文档 3-7 个标签为宜，最少 2 个，最多不超过 8 个
6. **大小写**：标签名首字母大写（如 `命令方块`），非全大写也非全小写

### 站点如何消费标签

标签数据在前端站点中的消费方式：

- **DocMeta 接口**：`lib/docs.ts` 中的 `DocMeta` 类型包含 `tags?: string[]` 字段，构建时从 frontmatter 中提取
- **文档列表页**：`DocsPageClient.tsx` 使用 `DocMeta.tags` 进行标签筛选
- **搜索**：标签文本参与全文搜索索引
- **相关推荐**：通过标签交集推荐相关文档

### 维护流程

1. 新增标签时，先在本文档的「完整标签索引」中添加，并更新对应命令的标签对照表
2. 删除标签时，确保没有任何文档正在使用该标签
3. 重命名标签时，需要在所有使用该标签的文档中批量替换
4. 每次更新标签体系后，需在本文档的 `updatedAt` 字段中更新日期
