## MCBECD 文档规范

这是 MCBECD 文档的唯一规范。**所有贡献者、维护者在编写和审核文档时，只需阅读本文档**——不存在其他平行标准。

本文档按「先规则、后细则」组织，不重复，也不交叉引用其他文件。

---

## 一、目录与分类

站点按**一级目录名**识别文档分类，分类名直接决定 URL 前缀。这个映射写在站点代码 `lib/docs.ts` 与 `lib/docUrl.ts` 中，**新增分类必须同步修改这两处**，否则文档不会被收录。

| 目录 | 用途 | 站点 URL | 站点是否展示 |
|------|------|----------|--------------|
| `basics/` | 基础文档：入门、语法、概念 | `/<文件名>/` | ✅ |
| `commands/` | 命令文档：每条命令一篇 | `/commands/<文件名>/` | ✅ |
| `community/` | 社区文档：教程、工具、玩法 | `/community/<文件名>/` | ✅ |
| `standards/` | 文档规范（本目录） | — | ❌ 仅供贡献者阅读 |

### 文件命名

| 类型 | 规则 | 示例 |
|------|------|------|
| 基础文档 | 语义化小写英文，连字符分隔 | `basics/getting-started.md` |
| 命令文档 | 命令名（小写，不含 `/`） | `commands/give.md` |
| 社区文档 | 纯数字编号，从 1 递增，不补零、不跳号、不复用 | `community/6.md` |

> [!WARNING]
> 文件名即文档 ID，决定路由与全部链接。改名等于改 URL，必须同步修正所有引用它的文档。

## 二、Frontmatter

每个 `.md` 文件顶部必须有 YAML frontmatter，用 `---` 包裹。

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `title` | string | ✅ | 文档标题，格式见下 |
| `description` | string | ✅ | 一句话描述，15–40 个汉字 |
| `author` | string | ✅ | 作者署名（社区名或 GitHub 用户名） |
| `updatedAt` | string | ✅ | 最后更新日期，格式 `YYYY-MM-DD` |
| `tags` | string[] | ⚠️ | 命令/社区文档必填，基础文档可选 |
| `hidden` | boolean | ❌ | 为 `true` 时不在列表分区中显示 |

### title 格式

| 类型 | 格式 | 示例 |
|------|------|------|
| 命令文档 | `/命令名` + **两个空格** + 中文名 | `"/give  给予物品"` |
| 社区文档 | 功能名，不超过 10 个汉字 | `"雪球菜单"` |
| 基础文档 | 简洁中文标题 | `"命令语法基础"` |

反例：`"give 命令"`（缺 `/`）、`"/give 给予物品"`（只有一个空格）、`"**/give**  给予物品"`（含 Markdown 格式）。

### description 与 author

- `description` 必须是完整的一句话，说清「这个功能做什么」，不要写「本文档介绍……」
- `author` 多人协作用逗号分隔：`"Alex, Steve"`
- `updatedAt` 每次改动内容都要更新，不得使用未来日期

## 三、章节结构

章节的**名称保持一致**（不要写「原理解释」「命令方块摆放」这类变体），**顺序按内容自行安排**。下面是常见结构，供参考，不必强行一致。

### 3.1 命令文档

| 顺序 | 章节 | 常见 |
|------|------|------|
| 1 | 概述（无标题开头段） | ✅ |
| 2 | `### 原理` | ✅ |
| 3 | `### 语法` | ✅ |
| 4 | `### 参数` | ✅ |
| 5 | 可选明细章节（见 3.6） | ❌ |
| 6 | `### 示例` | ✅ |
| 7 | `### 基岩版注意` | ✅ |
| 8 | `### 常见问题`（`<details>` 折叠） | ❌ |
| 9 | `### 相关命令` | ❌ |

### 3.2 社区文档

| 顺序 | 章节 | 常见 |
|------|------|------|
| 1 | 概述（无标题开头段） | ✅ |
| 2 | `### 原理` | ✅ |
| 3 | `### 前置指令` | ✅ |
| 4 | `### 搭建步骤` | ✅ |
| 5 | `### 常见问题`（`<details>` 折叠） | ❌ |
| 6 | `### 基岩版注意` | ❌ |

### 3.3 基础文档

基础文档没有固定章节，按内容自行分节；但**开头必须有概述段**（无标题）。

### 3.4 关于「原理」章节

「原理」解释这个命令或功能的工作机制，是文档里最有价值的部分——读者据此能举一反三，而不是只会照抄命令。位置由内容决定，但一篇文档内只出现一个「原理」章节，名称统一写作 `### 原理`。

### 3.5 各章节的写法

**概述**（无标题）：frontmatter 之后的第一段，1–3 句话概括功能。不要用标题，不要写套话。

**`### 原理`**：解释这个命令/功能的**工作机制**与**设计原因**。回答三个问题：

1. 它在底层做了什么？（机制）
2. 为什么必须这样做？（约束、历史原因、版本差异）
3. 有哪些边界行为？（什么时候会失效）

> [!IMPORTANT]
> 「原理」不是可选项。一篇没有原理的教程，读者只会照抄，一遇到变化就无法自行调整。

**`### 语法`**：用行内代码展示，`<参数>` 必填、`[参数]` 可选、`|` 二选一。多版本语法分别标注版本号。

**`### 参数`**：列表格式 `- <参数名> — 说明`，说明必须包含类型，不能只有一个类型名。

**`### 示例`**：至少 3 个，从简单到复杂，每个示例都要有效果说明。

**`### 前置指令`**（社区文档）：需要玩家提前在聊天栏执行的命令，每条用 `<CmdChat>` 组件。

**`### 搭建步骤`**（社区文档）：按步骤写明命令方块的**类型**（脉冲/重复/连锁/条件）与指令内容，每条指令用对应的 `<CmdXxx>` 组件。

**`### 常见问题`**（社区文档）：用 `<details>` 折叠。

**`### 基岩版注意`**：列出与 Java 版的差异、版本兼容性、OP 等级要求。用列表，**不使用提示框**。

### 3.6 可选明细章节

通常放在「参数」之后、「示例」之前：

`### 子命令一览`、`### 能力一览`、`### 常用实体 ID`、`### 常用方块 ID`、`### 常用物品 ID`、`### 常用粒子 ID`、`### 常用音效 ID`、`### 结构 ID`、`### 生物群系 ID`、`### 维度 ID`、`### 填充模式`、`### 遮罩模式`、`### 克隆模式`、`### 放置模式`、`### 方块状态`、`### 显示栏位`、`### 运算符`、`### 传送规则`、`### 骑乘规则`、`### 文字格式`、`### 预设时刻`

> 明细章节放在「参数」之后、「示例」之前，读起来最顺。

## 四、写作深度

| 类型 | 最低中文字数（不含代码块） | 最低示例数 |
|------|---------------------------|-----------|
| 命令文档 | 800 | 3 |
| 社区文档 | 400 | 按复杂度 |
| 基础文档 | 600 | 2 |

- 每个段落至少 2 句话；单句段落只用于过渡或强调
- 代码块内不加注释，说明写在代码块外
- 命令示例必须使用 `mcfunction` 语言标记

## 五、标签

标签从下表选取，不得自行创造。命令文档 3–7 个，社区文档 3–6 个，基础文档 0–2 个。

书写格式：`tags: ["标签A", "标签B"]`，顺序为 **领域 → 场景 → 属性**。

### 领域标签（命令文档必须且只能有 1 个）

`玩家`、`实体`、`方块`、`世界`、`物品`、`粒子`、`音效`、`计分板`、`标签`、`传送`、`执行`、`信息`、`状态`

### 场景标签（命令文档至少 1 个）

`命令方块`、`聊天栏`、`地图制作`、`服务器`、`自动化`、`生存`、`创造`、`红石`、`数据追踪`、`条件判断`、`多人`、`NPC`

### 属性标签（命令文档 1–2 个，OP 等级优先）

`OP1`、`OP2`、`危险`、`可逆`、`批量`、`单目标`、`多目标`、`即时`、`延迟`、`循环`、`基岩独有`、`版本敏感`、`网易差异`

### 社区专用标签

内容类型（选 1）：`教程`、`工具`、`玩法`、`技巧`、`红石电路`
技术栈（选 1–2）：`计分板`、`命令方块`、`标签系统`、`execute`、`原版`

### 元标签

`标准`（规范文档）、`入门`（新手文档）

## 六、交叉引用

### 链接写法

用反引号包裹命令名，并链接到对应文档：

```markdown
详见 [`/execute`](../../commands/execute/) 命令文档。
```

### 相对路径规则

路径**以站点 URL 深度为准**，末尾带 `/`、不带 `.md` 后缀：

| 当前文档 | URL 深度 | 链接到 | 写法 |
|----------|----------|--------|------|
| `basics/<name>.md` | 1 | `commands/give` | `../commands/give/` |
| `commands/<name>.md` | 2 | `commands/give` | `../give/` |
| `commands/<name>.md` | 2 | `basics/getting-started` | `../../basics/getting-started/` |
| `community/<name>.md` | 2 | `commands/give` | `../../commands/give/` |
| `community/<name>.md` | 2 | 同级 `community/3` | `../3/` |

### 其它规则

- 外部链接直接写完整 URL，站点引擎会自动加 `target="_blank"` 与新窗口图标
- 禁止裸写 URL（不加括号），链接文字必须可读

## 七、MD 组件

### 7.1 命令方块图标（7 种）

语法：`<CmdXxx>` 紧跟反引号命令，二者之间不能有空行，作为**独立段落**。图标由站点从 `/icons/cmd/<Xxx>.png` 载入。

| 组件 | 使用场景 |
|------|----------|
| `<CmdChat>` | 玩家在聊天栏手动输入的命令 |
| `<CmdImpulse>` | 脉冲方块：收到红石信号执行一次 |
| `<CmdRepeat>` | 重复方块：每个游戏刻执行 |
| `<CmdChain>` | 连锁方块：被前一个方块触发 |
| `<CmdConditionalImpulse>` | 条件脉冲：上一个成功时执行一次 |
| `<CmdConditionalRepeat>` | 条件重复：上一个成功时每刻执行 |
| `<CmdConditionalChain>` | 条件连锁：上一个成功时触发 |

```markdown
<CmdChat>`/scoreboard objectives add 雪球菜单 dummy`

<CmdRepeat>`/scoreboard players add @a 在线时间 1`

<CmdConditionalChain>`/scoreboard objectives remove 传送`
```

> [!NOTE]
> 组件里写命令**不加 `/` 前缀**（命令方块内执行时不输入 `/`），但 `<CmdChat>` 的内容需要 `/`。

### 7.2 GitHub 提示框

```markdown
> [!NOTE]
> 补充说明。

> [!TIP]
> 实用技巧。

> [!IMPORTANT]
> 关键要点。

> [!WARNING]
> 注意事项、版本兼容性。

> [!CAUTION]
> 危险或不可逆操作。
```

可自定义标题：`> [!WARNING] 基岩版独有`。规则：内容 1–3 句，不嵌套，内部不放代码块。`### 基岩版注意` 章节**不使用**提示框，改用列表。

### 7.3 折叠内容

```markdown
<details>
<summary>点击展开</summary>

折叠内容。

</details>
```

用于 FAQ 与补充说明。核心内容不得放进折叠。

### 7.4 其它

- **代码块**：命令用 `mcfunction`，JSON 用 `json`，配置用 `yaml`
- **表格**：GFM 表格，表头完整，列数建议不超过 5 列
- **内联代码**：命令名、参数名、物品 ID、选择器用反引号
- **键盘按键**：`<kbd>Ctrl</kbd>`

### 7.5 禁止使用

HTML 标签（除组件、`<kbd>`、`<details>`、`<summary>`）、脚注、裸 URL、图片、任务列表。

## 八、常见错误

| 错误 | 正确做法 |
|------|----------|
| 原理章节位置随便放 | 固定在概述之后、第一个 `###` |
| `title: "/give 给予物品"` | 两个空格：`"/give  给予物品"` |
| 链接写成 `./give` 或裸写 `/give` | 见第六章相对路径表 |
| 社区文档混用 `<CmdChat>` 与 `<CmdRepeat>` | 按 7.1 表判断执行环境 |
| 示例少于 3 个 | 命令文档至少 3 个，由简到繁 |
| 代码块内写注释 | 说明写在代码块外 |

## 九、提交与审核

### 提交前自检

- [ ] frontmatter 六个字段完整、格式正确
- [ ] `tags` 与第五章对照表一致
- [ ] 章节顺序符合第三章骨架（**原理在第二位**）
- [ ] 命令文档含语法、参数、示例、基岩版注意
- [ ] 示例 ≥ 3 个且由简到繁
- [ ] 所有命令引用为「反引号 + 相对链接」
- [ ] 命令方块指令使用了正确的 `<CmdXxx>` 组件
- [ ] 字数达标

### 维护者审核

1. 对照第五章检查标签
2. 检查 frontmatter 完整性
3. 检查第三章章节顺序（重点：原理位置）
4. 检查链接路径
5. 检查组件使用
6. 检查事实准确性（命令语法、版本行为）
7. 检查中文写作质量

### 修改本规范

本规范是唯一来源。如需变更，直接修改本文档，并在 PR 中说明原因；涉及标签增删时同步更新第五章对照表。
