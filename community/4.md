这套流程用 [`/give`](../../commands/give/) 与 [`/enchant`](../../commands/enchant/) 两条命令配合，为玩家配齐一整套附魔钻石装备，涵盖武器、工具与四件防具。基岩版的 `/give` 无法直接附魔，因此必须先给予未附魔的基础物品，再由玩家逐件手持后附魔。

### 原理

基岩版 [`/give`](../../commands/give/) 末尾的 `[组件]` 参数只接受四种 NBT 组件：`minecraft:can_place_on`、`minecraft:can_destroy`、`minecraft:keep_on_death` 与 `minecraft:item_lock`。这四种组件分别控制物品的可放置方块白名单、可破坏方块白名单、死亡是否保留与物品栏锁定，没有一种是用来存储附魔的。附魔数据在底层是附着于物品堆的一组「附魔条目」，由附魔 ID 与等级两个字段构成，存放在物品堆的另一块字段里，`/give` 的组件解析器根本不接收 `enchantments` 这类键。Java 版允许用 `/give` 的 NBT 直接写入附魔，而基岩版把「给予物品」和「添加附魔」拆成了两条独立的命令，这正是本流程要先 `/give` 再 `/enchant` 的根本原因。

[`/enchant`](../../commands/enchant/) 做的事情是直接改写目标「主手」物品堆的附魔列表：物品还没有该附魔时就新增一条记录，已有同种附魔但等级更低时就把它提升到指定等级。它不消耗经验或青金石，但复用了铁砧那套合法性校验——附魔是否适用于该物品、是否与已有附魔冲突、等级是否超过上限，任何一项不满足都会让整条命令失败。它最关键的作用域限制是只作用于主手（当前选中的快捷栏栏位），无法直接给物品栏其他格子或已穿在身上的盔甲附魔，因此每件装备都必须先拿在手上再附魔。

每件装备都取该附魔的合法最大等级，例如锋利 5、保护 4、耐久 3、经验修补 1。游戏在真正计算近战伤害、挖掘速度或耐久损耗时才读取这些等级并代入公式，等级越高对应的系数越大；为了防止无限堆叠，游戏为每种附魔设定了上限，`/enchant` 写入超过上限的等级（如 `sharpness 6`）会直接失败。此外部分附魔互斥，例如同一件盔甲上「保护」与「火焰保护」不能共存，所以附魔组合需要提前规划，不能无脑全部叠上。

### 前置指令

在聊天栏依次执行以下命令，把八件未附魔的钻石装备发给自己。这里的 `@s` 指执行者本人，物品会直接进入物品栏而无需拾取，优先与同类堆叠合并、再占用空槽位。

<CmdChat>`/give @s diamond_sword`

<CmdChat>`/give @s diamond_pickaxe`

<CmdChat>`/give @s diamond_axe`

<CmdChat>`/give @s diamond_shovel`

<CmdChat>`/give @s diamond_helmet`

<CmdChat>`/give @s diamond_chestplate`

<CmdChat>`/give @s diamond_leggings`

<CmdChat>`/give @s diamond_boots`

### 搭建步骤

以下附魔命令全部在聊天栏执行，无需命令方块。原因是 `/enchant` 只作用于主手，自动化的命令方块无法保证玩家手上拿的是哪一件装备，所以由玩家本人逐件手持后附魔最可靠。每附完一件再换下一件。

**第 1 步：附魔钻石剑（锋利 V + 耐久 III + 抢夺 III）**

拿起钻石剑后，依次执行：

<CmdChat>`/enchant @s sharpness 5`

<CmdChat>`/enchant @s unbreaking 3`

<CmdChat>`/enchant @s looting 3`

锋利 V 提升近战伤害，抢夺 III 提高怪物稀有掉落概率与掉落数量，耐久 III 降低使用工具时损耗耐久的概率。

**第 2 步：附魔钻石镐与钻石铲（效率 V + 耐久 III + 时运 III）**

镐与铲共用同一套附魔。先拿起钻石镐执行以下三条命令，再换钻石铲重复一遍：

<CmdChat>`/enchant @s efficiency 5`

<CmdChat>`/enchant @s unbreaking 3`

<CmdChat>`/enchant @s fortune 3`

效率 V 大幅加快挖掘速度，时运 III 提高矿石的额外掉落与沙砾掉燧石的概率，耐久 III 延长工具寿命。

**第 3 步：附魔钻石斧（效率 V + 耐久 III）**

拿起钻石斧后，依次执行：

<CmdChat>`/enchant @s efficiency 5`

<CmdChat>`/enchant @s unbreaking 3`

效率 V 加快伐木与破坏速度，耐久 III 降低损耗。斧的伤害加成主要来自锋利，本套未给斧附锋利，因此它主用于快速砍树。

**第 4 步：附魔三件防具（保护 IV + 耐久 III + 经验修补）**

头盔、胸甲、护腿共用同一套附魔。先拿起钻石头盔执行以下三条命令，再分别换胸甲、护腿各重复一遍：

<CmdChat>`/enchant @s protection 4`

<CmdChat>`/enchant @s unbreaking 3`

<CmdChat>`/enchant @s mending 1`

保护 IV 按等级减免大部分伤害类型，经验修补用吸收的经验球修复耐久，与耐久 III 叠加可让防具长期不需维修。

**第 5 步：附魔钻石靴子（保护 IV + 耐久 III + 摔落保护 IV + 经验修补）**

拿起钻石靴子后，依次执行：

<CmdChat>`/enchant @s protection 4`

<CmdChat>`/enchant @s unbreaking 3`

<CmdChat>`/enchant @s feather_falling 4`

<CmdChat>`/enchant @s mending 1`

靴子在三件防具的基础上多附摔落保护 IV，减免摔落伤害，与保护 IV 叠加进一步降低高处坠落的损失。

### 常见问题

<details>
<summary>为什么不能在 /give 里直接写附魔，像 Java 版那样？</summary>

基岩版 `/give` 的 `[组件]` 参数只支持 `can_place_on`、`can_destroy`、`keep_on_death`、`item_lock` 四种组件，不接受 `enchantments` 这类键。Java 版可以用 `/give` 的 NBT 直接写附魔，基岩版则必须先用 `/give` 得到物品，再手持后执行 [`/enchant`](../../commands/enchant/)。

</details>

<details>
<summary>附魔等级超过上限会怎样？</summary>

会直接失败。`/enchant` 复用了铁砧的校验规则，写入超过该附魔最大等级的数值（如 `sharpness 6`）会让整条命令失败，物品保持原样。所以本文全部取合法最大等级，例如锋利 5、保护 4、耐久 3。

</details>

<details>
<summary>为什么必须把装备拿在手上才能附魔？</summary>

因为 [`/enchant`](../../commands/enchant/) 只作用于目标的主手，也就是当前选中的快捷栏栏位。它不会去物品栏其他格子或已穿着的盔甲槽里找物品，所以每件装备都要先选中再附魔。

</details>

<details>
<summary>附魔后的装备死亡后会掉落吗？</summary>

默认会随死亡掉落。若想保留，可以开启游戏规则 `keepInventory`，让死亡后所有物品保留；该规则与装备是否附魔无关。

</details>

<details>
<summary>能更换附魔组合吗？</summary>

可以。替换命令中的附魔名与等级即可自定义组合，但要注意附魔之间的互斥关系，例如「保护」与「火焰保护」不能共存。完整的附魔名与最大等级见 [`/enchant`](../../commands/enchant/) 命令文档的「常用附魔 ID」表。

</details>

### 基岩版注意

- 需要 OP 等级 1 才能执行 [`/give`](../../commands/give/) 与 [`/enchant`](../../commands/enchant/)，在聊天栏执行时还需世界已开启「允许作弊」。
- 与 Java 版的主要差异：Java 版可用 `/give` 的 NBT 直接写附魔（如 `Enchantments`），基岩版不支持，必须改用 `/enchant`；基岩版 `/enchant` 的附魔 ID 不带命名空间（如 `sharpness`），Java 版带命名空间前缀（如 `minecraft:sharpness`）。
- 版本兼容：1.19.50 起，对已持有同种附魔的物品再次执行 `/enchant` 会直接设为请求的等级，不再叠加；1.19.20 起 `/enchant` 才可作用于手持武器或工具的实体，此前只能作用于玩家。
- 物品 ID 使用下划线命名（如 `diamond_sword`、`diamond_chestplate`），不要写成带空格的「diamond sword」。
