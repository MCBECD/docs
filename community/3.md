丢雪球打开菜单，抬头选择选项，低头关闭。支持传送主城、原地去世、生存模式、设重生点、发起传送和接受传送。

### 原理解释

**计分板 = 菜单的状态机。**

整个菜单用一个 `雪球菜单` 计分板记录每位玩家当前的状态：分数 `0` 表示菜单关闭，`1`~`6` 分别对应六个选项。玩家丢雪球时，指令 2 用 `@p[r=2]` 找到雪球附近 2 格内的玩家，给他的分数 +1（打开菜单）。选择、执行、重置，本质都是「读取分数 → 触发对应指令 → 把分数写回」的循环。

**`rx` / `rxm` 怎么检测抬头和低头？**

`rx` 是「最大俯仰角」，`rxm` 是「最小俯仰角」。基岩版中俯仰角朝上看为负（-90° 是正上方）、朝下看为正（+90° 是正下方）。所以：

- `rx=-88` → 只选中俯仰角 ≤ -88° 的玩家，即**抬头看天**（用来确定选项）
- `rxm=88` → 只选中俯仰角 ≥ 88° 的玩家，即**低头看地**（用来关闭菜单 / 取消传送）

指令里用 `@a[scores={雪球菜单=1},rx=-88]` 这种写法，把「分数状态」和「视角方向」叠加成精确的触发条件。

**传送为什么单独用一个 `传送` 计分板？**

「发起传送」和「接受传送」是两名不同玩家、跨越多个游戏刻的异步流程，需要记住「谁发起了传送」。用独立的 `传送` 计分板记录发起者，用 `计时` 计分板做 60 秒倒计时；超时或低头取消时直接删除整个 `传送` 计分板即可复位。用计分板而不是 tag 的原因：玩家离线后 tag 无法清除，但计分板可以随时删除。

### 命令方块摆放

将以下三组命令方块**按顺序摆放**，箭头方向沿指令编号递增。复制指令前请先查看文末常见问题。

#### 一、雪球菜单运行

**指令 1** — 给予命名雪球（循环/无条件/保持开启/延迟 0）

<CmdRepeat>`/replaceitem entity @a slot.hotbar 8 destroy snowball 16 0 {"minecraft:item_lock":{"mode":"lock_in_slot"},"minecraft:display_name":{"value":"雪球菜单"}}`

**指令 2** — 丢雪球时计分 +1（连锁/无条件/保持开启/延迟 0）

<CmdChain>`/execute at @e[type=snowball] run scoreboard players add @p[r=2] 雪球菜单 1`

**指令 3** — 丢雪球时播放音效（连锁/无条件/保持开启/延迟 0）

<CmdChain>`/execute at @e[type=snowball] run playsound random.orb @p[r=2]`

**指令 4** — 清除雪球实体（连锁/无条件/保持开启/延迟 0）

<CmdChain>`/execute at @a[scores={雪球菜单=1..}] run kill @e[type=snowball,c=1,r=2]`

**指令 5** — 显示菜单（连锁/无条件/保持开启/延迟 0）

<CmdChain>`/execute as @a[scores={雪球菜单=1..6}] run titleraw @s actionbar {"rawtext":[{"text":"lb 『雪球菜单』\n▶==================◀\n"},{"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={雪球菜单=1}]"},{"text":" 6"},{"text":" e"}]}},{"text":"①.『传送主城』\n"},{"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={雪球菜单=2}]"},{"text":" 6"},{"text":" e"}]}},{"text":"②.『原地去世』\n"},{"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={雪球菜单=3}]"},{"text":" 6"},{"text":" e"}]}},{"text":"③.『生存模式』\n"},{"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={雪球菜单=4}]"},{"text":" 6"},{"text":" e"}]}},{"text":"④.『设重生点』\n"},{"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={雪球菜单=5}]"},{"text":" 6"},{"text":" e"}]}},{"text":"⑤.『发起传送』\n"},{"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={雪球菜单=6}]"},{"text":" 6"},{"text":" e"}]}},{"text":".『接受传送』\n"},{"text":"b==================\na抬头确定c低头关闭\n\n\n\n\n"}]}`

**指令 6** — 分数上限为 6（连锁/无条件/保持开启/延迟 0）

<CmdChain>`/scoreboard players set @a[scores={雪球菜单=7..}] 雪球菜单 1`

**指令 7** — 低头时显示关闭提示（连锁/无条件/保持开启/延迟 0）

<CmdChain>`/title @a[scores={雪球菜单=!0},rxm=88] actionbar lcMenu Offf ｜ 7已关闭`

**指令 8** — 低头时播放音效（连锁/无条件/保持开启/延迟 0）

**指令 9** — 低头时重置分数（连锁/无条件/保持开启/延迟 0）

<CmdChain>`/scoreboard players set @a[scores={雪球菜单=!0},rxm=88] 雪球菜单 0`

#### 三、处理传送超时与低头取消

> 第三条指令使用**红石块**保持开启而非"循环"模式，因为网易版循环命令方块延迟不准，红石控制可保证 60 秒准确。

**指令 27** — 倒计时递减（循环/无条件/红石控制/延迟 20）

<CmdRepeat>`/execute if score 计时 雪球菜单 matches 0..60 run scoreboard players remove 计时 雪球菜单 1`

**指令 28** — 超时后删除计分板（连锁/无条件/保持开启/延迟 0）

<CmdChain>`/execute if score 计时 雪球菜单 matches ..-1 run scoreboard objectives remove 传送`

**指令 29** — 超时公告（连锁/有条件/保持开启/延迟 0）

<CmdConditionalChain>`/tellraw @a {"rawtext":[{"text":"l〈d世界公告f〉r超时无人同意或发起传送者离线，已自动取消传送请求。"}]}`

**指令 30** — 低头取消传送（公告）

<CmdChain>`/execute as @a[scores={传送=1},rxm=88] run tellraw @a {"rawtext":[{"text":"l〈d世界公告f〉r玩家b"},{"selector":"@s"},{"text":"r已取消传送请求。"}]}`

**指令 31** — 低头取消传送（删除计分板）

<CmdChain>`/execute as @a[scores={传送=1},rxm=88] run scoreboard objectives remove 传送`

### 常见问题

<details>
<summary>雪球菜单离远了没有用？</summary>

没有设置常加载区域。必须把命令方块放在常加载区域才能全图生效。基岩版 1.20+ 使用 [`/time`](../../commands/time/) 命令。

站在命令方块位置执行：

```
/tickingarea add ~-10 ~-10 ~-10 ~10 ~10 ~10 菜单加载
```

即可将周围 21×21×21 范围设为常加载。范围不够可调整坐标或添加多个区域。

</details>

<details>
<summary>回城会一直原地罚站 / 视角被锁定？</summary>

重置雪球菜单分数的指令没生效。可能原因：抄错/漏抄；命令方块箭头方向不对；顺序错（重置指令必须在最后）；还没做完就使用。解决办法：先关闭"启用命令方块"，全部做完再开启。

</details>

<details>
<summary>全服公告刷屏？</summary>

发起/接受传送的公告刷屏 → 重置失败，同上。超时公告刷屏 → 没把超时显示的命令方块设为"有条件"。

</details>

<details>
<summary>想要黄色角标的可移动雪球？</summary>

将第一条给雪球的指令替换为：

```
/give @a[hasitem={item=snowball,data=1,quantity=0}] snowball 16 1 {"minecraft:item_lock":{"mode":"lock_in_inventory"},"minecraft:display_name":{"value":"雪球菜单"}}
```

背包满了可加循环指令 `/clear @s snowball`。若要死亡不掉落，加上 `"minecraft:keep_on_death":{}` 组件。

</details>

<details>
<summary>菜单显示复制进去变成了 ***？</summary>

多复制几次，有几率成功。全服公告变成 *** 则是因为玩家名字含屏蔽词，无法解决。部分符号变成问号是 iOS 系统问题，可让安卓朋友帮忙复制。

</details>

<details>
<summary>一直显示"互传通道被占用"？</summary>

超过 60 秒仍占用，说明传送计分板未被移除。检查第三组指令是否抄错，特别是删除计分板的指令是否设为"有条件"。

</details>

<details>
<summary>为什么用计分板而不是 tag？</summary>

离线玩家无法清除 tag，但计分板可直接删除（`/scoreboard objectives remove`），避免发起者下线后仍被标记。删除计分板也比重置更省性能。

</details>

### 基岩版注意

- 部分命令（如 `/replaceitem`）在较新版本中可能被 `/item replace` 替代，如果报错请尝试替换
- 网易版与国际版在命令语法上存在细微差异，本文档基于国际版编写
- [`/title`](../../commands/title/) 中的 `titleraw` 子命令和 `rawtext` 格式为基岩版特有语法
- 传送倒计时的循环命令方块建议使用红石控制而非「保持开启」，以保证延迟准确
- 涉及的 [`/scoreboard`](../../commands/scoreboard/)、[`/execute`](../../commands/execute/)、[`/tp`](../../commands/tp/)、[`/kill`](../../commands/kill/)、[`/gamemode`](../../commands/gamemode/)、[`/gamerule`](../../commands/gamerule/) 均需要 OP 等级 1
